# Ambitious Roadmap

This is a review draft for turning the knowledge bank from a static reference into a working AI-native founder operating system.

## North Star

By the end of this roadmap, the knowledge bank should help produce shipped products, better agent delegation, measurable eval habits, and a compounding source graph. It should not become a passive note archive.

## 12-Month Outcomes

| Outcome | Target |
| --- | --- |
| Shipped products | 3 public or customer-facing product experiments |
| Customer proof | 30 direct conversations, 10 strong problem confirmations, 3 paid or pilot asks |
| Agent leverage | 20 reusable agent workflows with acceptance criteria and verification |
| Evals discipline | 10 lightweight eval sets tied to real workflows or rejected outputs |
| Knowledge graph | 200 high-quality source notes, 30 promoted people/tools/topics, no unsourced major claims |
| Public artifact | A polished public-safe version of the knowledge bank or a derived field guide |

## Phase 1: Operating Baseline

Timebox: 2 weeks

| Goal | Deliverable | Acceptance Criteria |
| --- | --- | --- |
| Make maintenance repeatable | Generator, checks, seeds, link checks | `npm run check` passes and generation is idempotent |
| Define founder scorecard | Weekly metrics page | Tracks shipped work, customer proof, agent leverage, evals, and learning |
| Build failure logs | Agent failure and product failure templates | Every rejected agent task creates a reusable lesson |

## Phase 2: Evals And Production AI Spine

Timebox: 4 weeks

| Goal | Deliverable | Acceptance Criteria |
| --- | --- | --- |
| Promote evals mentors | Full pages for evals and AI engineering candidates | Each page has source evidence, practices, exercises, and prompts |
| Create eval playbook | Practical eval lifecycle | Covers failure collection, rubric design, regression cases, and review cadence |
| Build first eval harness | One real workflow eval set | At least 20 cases from real or plausible failures |
| Add observability checklist | Production AI readiness checklist | Covers inputs, outputs, reviewer action, cost, latency, drift, and fallback |

## Phase 3: Product Discovery Engine

Timebox: 6 weeks

| Goal | Deliverable | Acceptance Criteria |
| --- | --- | --- |
| Map problem inventory | 25 business workflow pains | Each has buyer, pain, current workaround, urgency, and AI fit |
| Run customer discovery | 15 conversations or async interviews | Every conversation produces structured notes and next action |
| Select product wedge | One narrow paid workflow | Has target user, manual process, AI leverage point, and proof metric |
| Publish positioning | Landing page or explainer | Promise is concrete enough to reject or buy |

## Phase 4: Agentic Product Factory

Timebox: 8 weeks

| Goal | Deliverable | Acceptance Criteria |
| --- | --- | --- |
| Standardize agent delegation | Reusable task specs | Specs include goal, context, constraints, files, risks, and verification |
| Build parallel review loops | Multi-agent review playbook | At least 5 tasks use independent builder/reviewer passes |
| Create product template | Static/demo/app starter workflow | Can go from idea to demo with QA checklist in one focused sprint |
| Add Browser QA habit | Rendered QA checklist | Every frontend change has smoke, search/navigation, console, and responsive checks |

## Phase 5: Public-Safe Distribution Layer

Timebox: 6 weeks

| Goal | Deliverable | Acceptance Criteria |
| --- | --- | --- |
| Public-safe redaction path | Redaction checklist and scanner | No personal paths, private notes, credentials, or employer/client detail |
| Derived field guide | Public-facing lessons from the private bank | Useful without exposing private operating notes |
| Build-in-public cadence | Weekly artifact | Each post ties to shipped work, customer learning, or evaluation insight |
| Source graph credibility | Source quality dashboard | Highlights primary sources, weak claims, stale tool snapshots, and review queue |

## Phase 6: One-Person Company System

Timebox: 12 weeks

| Goal | Deliverable | Acceptance Criteria |
| --- | --- | --- |
| Launch product experiment 1 | Narrow AI workflow product | User can try it; at least 5 target users see it |
| Launch product experiment 2 | Second wedge or iteration | Decision is based on customer proof, not builder excitement |
| Ask for money | Paid pilot, preorder, or explicit rejection | At least 3 direct paid asks |
| Consolidate operating system | Founder OS dashboard | Weekly review, roadmap, evals, source graph, and product ledger connect |

## Monthly Review Questions

- What shipped that a real user could inspect, use, reject, or pay for?
- Which agent workflows now compound instead of staying ad hoc?
- Which evals changed a product or engineering decision?
- Which sources changed behavior rather than adding trivia?
- What should be killed, simplified, or made public-safe?

## Immediate Next Bets

1. Build a product-opportunity ledger from recurring business workflows.
2. Add an eval lifecycle playbook connected to the newly promoted evals mentors.
3. Create a founder scorecard page that pulls weekly actions into measurable outcomes.
4. Add public-safe review as a default pre-publish gate.
5. Pick one small product wedge and force it through customer discovery before implementation.
